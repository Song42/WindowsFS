# WindowsFS 용량 기록 설계안

대시보드의 **용량 기록**에서 최근 여유 공간이 줄어든 시각을 선택하면, 같은 시간에 커지거나 사라진 파일 묶음과 관찰된 프로세스를 확인한다. 사용자가 추적을 켠 시점부터 기록한다. 아래 주기와 보관 한도는 구현 후 측정할 초깃값이다.

## 화면과 트레이

- 용량 기록 상단에 추적 시작·일시 정지와 기간 선택을 둔다. 기본 기간은 24시간이다. 첫 버전의 대상은 현재 분석에 포함된 로컬 경로다. 볼륨 여유 공간 그래프에는 측정 범위를 볼륨 전체로 표기한다.
- 그래프 아래 목록은 최근순과 용량순으로 전환한다. 한 행은 시간대, 프로그램, 용도, 증가·감소량, 파일 수를 보여준다. 행을 펼치면 파일별 경로, 이전·이후 크기, 마지막으로 관찰된 작업과 시각, 판단 근거가 나온다. 설정·캐시 같은 용도는 파일 단위로 판단해 한 프로그램 안에서도 분리한다.
- 추적을 켜면 현재 사용자 세션에 트레이 아이콘이 생긴다. 창의 닫기 버튼은 창만 숨긴다. 다시 실행하거나 아이콘을 누르면 기존 창을 연다. 메뉴는 **열기 / 추적 일시 정지·재개 / 종료**로 구성한다. 정지 중에도 트레이에서 재개할 수 있다. 백그라운드 모드를 사용하지 않으면 닫기는 기존처럼 종료한다.
- 트레이 숨김은 현재의 종료 처리와 분리한다. 명시적 종료나 로그오프에서는 수집을 멈추고 대기 중인 기록을 제한된 시간 동안 저장한다. 사용자별 단일 인스턴스와 Explorer 재시작 후 아이콘 재등록을 지원한다. 첫 버전은 로그인 자동 시작과 상주 Windows 서비스 설치를 요구하지 않는다. [Windows 알림 영역](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area)

## 수집과 판단

| 질문 | 수집 방식 | 화면에서의 해석 |
| --- | --- | --- |
| 디스크가 실제로 얼마나 찼나? | 기존 `DiskSpaceReader`로 볼륨별 전체 여유 바이트를 30초마다 읽는다. 같은 볼륨의 분석 경로가 여러 개여도 한 번만 측정한다. | 두 측정 사이 볼륨의 순변화. 여러 앱이 동시에 활동할 수 있다. |
| 어떤 파일이 변했나? | NTFS에서 접근 가능한 기존 USN 변경 저널을 읽고, 변경된 파일의 크기·할당량 등 메타데이터만 재조회한다. 기준값과 변경값을 볼륨 ID와 파일 ID로 연결한다. | 생성·증가·축소·이동·삭제, 또는 이전 크기 미상. 기본 모드에서 저널 접근이 안 되면 볼륨 그래프만 유지한다. |
| 누가 작업했나? | 상세 추적을 켜면 Windows 실시간 이벤트 추적(ETW)의 파일 작업과 프로세스·스레드 생명주기를 연결한다. 쓰기·삭제 요청과 관찰된 결과를 구분한다. | 마지막 쓰기 프로세스, 삭제를 요청한 프로세스, 관련 앱을 별도로 표시한다. 여러 프로세스가 썼으면 공동 작업으로 남긴다. |
| 무엇을 위한 파일인가? | 기존 정리 분석의 설치 위치·표준 데이터 경로 규칙을 재사용한다. | 예: 브라우저 캐시(경로 일치), 설치 구성요소(설치 등록 위치 일치), 용도 미확인. 프로그램의 실제 의도는 경로만으로 확정할 수 없다. |

ETW 쓰기 크기는 요청한 I/O 바이트다. 같은 블록을 반복해서 써도 할당량은 그대로일 수 있다. 이벤트의 파일 객체·이름을 작업 수명 안에서 매칭하고, 스레드와 프로세스는 시작 시각까지 확인해 ID 재사용을 처리한다. 일치가 불확실하면 프로세스는 **미확인**으로 둔다. 파일 증가량 전체를 마지막 작성자에게 배정하지 않는다. [파일 I/O 이벤트](https://learn.microsoft.com/en-us/windows/win32/etw/fileio-readwrite) · [커널 추적 세션](https://learn.microsoft.com/en-us/windows/win32/etw/configuring-and-starting-a-systemtraceprovider-session)

현재 분석에는 모든 파일의 개별 크기가 저장되지 않는다. 추적 시작 시 기존 스캔 수치를 과거 할당량으로 사용하지 않는다. 첫 버전은 변경된 항목부터 기준값을 쌓고, 이전값이 없는 기존 파일의 첫 변경·삭제는 바이트를 미상으로 남긴다. 새 파일의 생성을 처음부터 관찰한 경우에만 0에서 시작한다. 첫 실행이나 재개 때 전체 드라이브를 자동 재스캔하지 않는다.

절전·종료·일시 정지·버퍼 유실·드라이브 분리를 기록한다. 재개 시 같은 저널 ID와 유효한 체크포인트가 있으면 변경된 항목만 보충한다. 사라진 중간 크기나 과거 프로세스는 복원하지 않는다. 저널이 교체됐거나 구간이 잘렸으면 그래프에 공백을 남기고 새 기준점을 잡는다. 저널을 생성하거나 시스템 감사 설정을 바꾸지 않는다. ETW 권한이 필요한 환경은 사용자가 상세 추적을 켤 때만 별도 수집기의 권한을 요청하고, 실패해도 기본 추적을 유지한다. [NTFS 변경 기록의 범위](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journal-records)

## 삭제로 확보한 공간

파일 상세에는 **삭제 전 논리 크기**와 **마지막으로 확인한 할당량**을 별도로 둔다. 같은 볼륨 내 이름 변경·폴더 이동·휴지통 이동은 공간 회수로 집계하지 않는다. 하드 링크 하나만 지워졌거나 마지막 핸들이 열려 있으면 회수량을 확정하지 않는다. 마지막 링크 제거와 이전 할당량이 확인된 경우에만 **삭제로 회수 추정**에 반영한다. 압축·희소 파일은 확인 가능한 할당량을 쓰고, 불확실한 값은 합계와 분리한다. [파일 할당량·링크 수·삭제 대기 상태](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_standard_info)

예를 들어 휴지통 비우기로 2.0 GB 회수가 추정되고 같은 구간에 여유 공간이 1.7 GB 늘었다면 두 수치를 그대로 보여준다. 0.3 GB 차이는 다른 작업의 영향일 수 있다. 볼륨 그래프는 사용자 할당량에 따라 달라질 수 있는 호출자 가용량과 구분해 전체 여유량을 사용한다. [볼륨 여유 공간 측정](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)

## 저장과 성능

- 현재 규칙은 분석 캐시 한 파일과 교체용 임시 파일에만 런타임 쓰기를 허용한다. 구현 시 제안하는 예외는 고정된 앱 전용 경로 `%LOCALAPPDATA%\WindowsFS\History\history.db`와 SQLite의 필수 보조 파일(WAL·SHM 등), 해당 디렉터리 생성까지다. 기존 분석 캐시에 추적 데이터를 계속 덧쓰지 않는다. 분석 삭제와 기록 보관 기간은 독립적으로 관리한다.
- 기록은 볼륨 표본, 관찰한 파일의 마지막 상태, 파일 변경 묶음, 수집 공백, 저널 체크포인트로 구성한다. 프로세스는 실행 파일명과 필요한 로컬 식별값만 보관한다. 파일 본문·미리보기·명령줄·환경 변수는 수집하지 않고, 경로와 이력은 PC 안에서만 사용한다.
- 수집과 화면을 분리하고, 크기 제한이 있는 큐에서 같은 파일의 연속 변경을 짧은 시간 창으로 묶는다. 파일 상태·변경 묶음·체크포인트를 한 트랜잭션에 기록해 재시작 시 중복 반영을 막는다. 원시 추적 파일을 만들지 않으며 자체 기록 DB 쓰기는 앱별 변경 목록에서 제외한다. 볼륨 전체 여유량에는 이 DB의 실제 사용량도 반영된다.
- 초기 보관안은 상세 7일, 시간별 요약 30일, 저장 예산 128 MB다. 한도에 가까워지면 오래된 상세와 파일 기준값부터 정리한다. 기준값을 잃은 파일은 다음 변경 때 다시 미상으로 시작한다. 지속적인 과부하나 디스크 부족은 공백으로 기록하고 수집 부하를 줄인다.

## 구현 순서와 수용 기준

1. **트레이와 볼륨 그래프.** 추적 중 창을 닫았다 열어도 한 인스턴스에서 표본이 이어지고, 종료·재개·절전 구간이 구분돼야 한다.
2. **파일 증감과 삭제 추정.** 임시 테스트 볼륨에서 추가 쓰기, 같은 길이 덮어쓰기, 축소, 이동, 휴지통 이동, 하드 링크 삭제를 재현한다. 기준값 없는 삭제·유실 구간을 0 B로 오인하거나 같은 변경을 두 번 합산하면 실패다.
3. **프로세스와 용도.** 두 테스트 프로세스가 같은 파일을 번갈아 쓸 때 마지막 관찰자와 전체 증가량을 구분한다. 권한 거절·이벤트 폭주에서도 UI가 응답해야 한다. 대량 소파일 변경, 유휴 CPU·메모리, DB 증가량을 측정해 수집 주기와 보관 한도를 결정한다.
