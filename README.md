# WindowsFS

Windows 11을 위한 가볍고 확장 가능한 디스크 용량 분석 앱입니다. 어느 폴더와 파일이 공간을 많이 차지하는지, 탐색 중인 위치에서 바로 확인할 수 있습니다.

## 초기 버전

- 연결된 로컬 드라이브 또는 지정한 폴더 분석
- 큰 파일 상위 1,000개와 폴더별 누적 용량 탐색
- 확장자별 용량 집계
- 블록·도넛 공간 구성 전환, 목록 내 이름·경로 검색, 선택 경로 복사
- 백그라운드 병렬 분석, 진행 상황 표시, 취소 후 부분 결과 확인
- 완료된 분석 결과 자동 저장 및 다음 실행 시 복원
- 저장된 분석 삭제 및 현재 결과 초기화
- 알려진 Windows 시스템 항목의 용도·관리 주체·필요성·정리 시 주의사항 안내
- 음악·영상의 MediaInfo 세부정보: 컨테이너, 영상·오디오·자막 트랙, 코덱, 재생 시간, 비트레이트, 해상도, 프레임률, 색상/HDR, 채널, 태그
- Windows 탐색기에서 선택 항목의 위치 열기
- 한국어 인터페이스와 네이티브 WPF 화면

사이드바 없이 대시보드의 **가장 큰 파일 / 폴더 탐색 / 파일 형식** 카드에서 상세 화면으로 이동합니다. 창 상단의 **대시보드** 버튼으로 돌아옵니다. 화면 전환은 저장된 분석을 사용하며 재스캔하지 않습니다. 폴더 탐색의 **현재 경로**에서 각 폴더를 눌러 분석 범위 내의 상위 폴더로 이동할 수 있습니다. 메인 화면의 전체·개별 드라이브 선택 및 용량 위젯은 향후 UI 결정까지 제외하고, 분석 대상 표시와 읽기 전용 폴더 선택은 가장 큰 파일 페이지를 제외한 화면에 유지합니다.

분석과 폴더 탐색은 파일 이름, 경로, 크기 같은 **메타데이터만 읽습니다**. 파일을 삭제·변경하지 않습니다. 미리보기는 명시적으로 요청한 경우에만 제한된 범위의 내용을 읽습니다. 완료된 분석 결과는 현재 Windows 사용자의 PC에 저장하며, 서버로 전송하지 않습니다. 경로 복사와 탐색기 열기는 사용자가 선택한 항목을 Windows 클립보드 또는 탐색기로 전달합니다.

**읽기 전용은 모든 버전에 적용되는 제품 원칙입니다.** 실제 사용자·시스템 파일과 폴더의 생성·삭제·이동·복사·이름 변경·수정 기능은 추가하지 않습니다. 분석 대상 선택도 원본 변경 명령이 없는 앱 내부 폴더 선택창을 사용합니다. 앱의 파일 쓰기는 분석 저장용 캐시 폴더, 캐시 파일과 원자적 저장을 위한 임시 파일에만 한정됩니다. **저장된 분석 삭제**는 이 앱 자체 캐시만 삭제합니다.

공간 구성 상단의 **블록 / 도넛**으로 표시 방식을 전환합니다. 두 방식은 같은 분석 결과와 용량 비율을 사용하며, 전환 시 재스캔하지 않습니다. 폴더 영역 클릭 또는 방향키·Enter로 하위 폴더를 탐색할 수 있습니다. 도넛 중앙에는 전체 용량 또는 선택한 항목의 용량·비율이 표시됩니다.

공간 구성의 오른쪽 경계와 세부정보의 왼쪽 경계를 드래그하면 각각 너비를 조절할 수 있습니다. 조절 경계에 키보드 포커스가 있으면 좌우 방향키로도 조절합니다. 선택한 너비는 앱 실행 중 파일·폴더 전환이나 패널 닫기·열기에도 유지됩니다. 목록과 설명을 표시할 공간이 부족할 때만 지도를 숨기고, 창을 넓히면 선택한 너비로 다시 표시합니다. 도넛의 정보 목록이 오른쪽에 배치되면 도넛과 세로 중앙을 맞춥니다.

## 미디어 세부정보

세부정보의 **General**은 기본으로 펼쳐져 있으며 접기·펼치기가 가능합니다. **Windows 파일 설명 / MediaInfo / 미리보기** 섹션은 기본으로 접혀 있으며, 앱 실행 중 모든 섹션의 펼침·접힘 상태는 다른 파일이나 폴더를 선택해도 유지됩니다. 미리보기 미지원 항목에서는 미리보기 섹션을 숨깁니다.

음악·영상 파일의 **MediaInfo** 섹션을 처음 펼칠 때 MediaInfoLib로 정보를 읽습니다. 같은 파일을 선택한 상태에서 다시 펼치면 메모리에 보관한 결과를 사용합니다. 다른 항목을 선택하면 이전 읽기를 취소하고, 섹션이 펼쳐져 있다면 새 파일의 정보를 읽습니다. 파일에 기록되어 있고 라이브러리가 인식한 정보만 표시하며, 폭이 충분하면 두 열로 배치합니다.

MP3, WAV, FLAC, AAC, M4A, Ogg/Opus, MP4, MKV, AVI, MOV 등 일반적인 오디오·영상 컨테이너를 지원합니다. 재생 지원 형식과 정보 조회 지원 형식은 별개입니다. 로컬 파일을 읽기 전용으로 열며, 네이티브 라이브러리에는 경로 대신 바이트를 전달합니다. 재생목록, 외부 참조 영상, 압축된 QuickTime 메타데이터와 오프라인 파일은 제외합니다. 읽기는 최대 64 MB·128회 탐색·8초 범위이며 제한에 도달하면 부분 정보 상태를 표시합니다. 미디어 정보나 내용은 디스크에 저장하거나 서버로 보내지 않습니다.

## 시스템 항목 설명

목록에서 알려진 시스템 항목을 선택하거나 해당 폴더로 이동하면 설명 패널에 용도, 일반적인 관리 주체, 필요성과 정리 방법이 표시됩니다. 패널의 공식 문서 버튼에서 근거를 확인할 수 있습니다. 설명 자체는 앱에 포함되어 있어 항목을 선택할 때 파일을 열거나 인터넷에 조회하지 않습니다.

분류는 Windows의 표준 위치와 일치하는 항목에만 적용합니다. 문서·사진·사용자 폴더, 시스템 파일과 이름만 같은 복사본, 시스템 폴더 안의 임의 파일에는 설명을 붙이지 않습니다. 경로 기반 안내는 해당 파일의 실제 생성자나 진위를 검증한 결과가 아닙니다. 안내된 폴더 아래의 모든 파일이 Windows에서 생성되었다는 뜻도 아닙니다. 앱은 시스템 파일을 삭제하거나 설정을 변경하지 않습니다.

## 저장된 분석 결과

분석이 완료되면 최근 결과 한 개를 자동 저장합니다. 앱을 다시 열면 파일 트리를 재스캔하지 않고 저장된 결과를 복원하므로, 용량 지도와 큰 파일 목록을 바로 탐색할 수 있습니다.

- 저장 위치: `%LOCALAPPDATA%\WindowsFS\Cache\latest.scan.json.gz`
- 저장 내용: 분석 대상, 분석 시각, 폴더 경로와 누적 용량, 큰 파일 목록, 확장자별 집계 및 분석 통계
- 저장된 결과는 **표시된 분석 시점의 정보**입니다. 이후 파일 생성·이동·삭제는 자동 반영하지 않으며, 최신 정보가 필요할 때 다시 분석하세요.
- 다른 대상을 포함해 새 분석이 완료되면 이전 저장 결과를 교체합니다. 취소된 부분 결과는 화면에서만 보여주고, 기존 완료 결과를 덮어쓰지 않습니다.
- 화면 상단의 **저장된 분석 삭제**는 로컬 캐시와 현재 화면의 분석 결과를 지웁니다. 실제 파일·폴더, 선택한 분석 대상과 공간 구성 방식은 유지됩니다. 삭제 후 다시 실행해도 자동 분석하지 않습니다.
- 분석·저장·복원·삭제 중에는 삭제 버튼이 비활성화됩니다. 손상된 캐시도 삭제할 수 있으며, 삭제 실패 시 현재 결과는 유지됩니다.
- 저장 중 오류나 종료가 발생하면 기존 저장 결과를 보존합니다. 손상되었거나 지원하지 않는 형식의 캐시는 안내 후 건너뛰며 새로 분석할 수 있습니다.

캐시는 저장소와 별개인 사용자별 로컬 앱 데이터 폴더에 둡니다. 파일 이름과 경로를 포함하는 압축 JSON이며 별도 암호화는 하지 않으므로, Windows 사용자 폴더의 접근 권한으로 보호됩니다. 앱은 이 파일을 업로드하거나 동기화하지 않습니다. 캐시를 외부에 공유하지 마세요.

## 실행

개발 환경은 Windows 11과 **.NET 10 SDK**가 필요합니다. .NET Runtime만 설치되어 있다면 SDK를 추가로 설치해야 합니다.

```powershell
./scripts/run.ps1
```

스크립트는 `.tools/dotnet/dotnet.exe`가 있으면 이를 사용하고, 없으면 `PATH`의 `dotnet`을 사용합니다. SDK를 자동 다운로드하거나 시스템 설정을 변경하지 않습니다.

특정 폴더를 바로 분석하려면 `./scripts/run.ps1 -Scan 'C:\Data'`를 사용하세요. 배포된 앱도 `WindowsFS.exe --scan 'C:\Data'` 형식으로 실행할 수 있습니다.

배포용 앱 생성:

```powershell
./scripts/publish.ps1
```

결과는 `.artifacts/publish/win-x64/`에 생성됩니다. 폴더 전체를 복사한 뒤 `WindowsFS.exe`를 실행하세요. 런타임이 포함되어 있어 대상 PC에 .NET을 별도로 설치할 필요가 없습니다. ARM64용 빌드는 `./scripts/publish.ps1 -Runtime win-arm64`로 생성할 수 있습니다.

GitHub Actions도 Windows에서 빌드, 코어 검증, WPF 뷰 모델 검증을 수행하고, 실행 파일과 런타임이 담긴 `WindowsFS-win-x64` 아티팩트를 만듭니다.

## 용량을 읽는 방법

표시되는 용량은 파일의 **논리적 크기** 합계입니다. Windows의 실제 디스크 사용량과는 다를 수 있습니다.

- 압축 파일, 희소 파일의 실제 할당 크기는 별도로 계산하지 않습니다.
- 하드 링크는 경로마다 집계하므로 같은 데이터가 중복 계산될 수 있습니다.
- 접근 권한이 없는 폴더, 정션·심볼릭 링크 등 재분석 지점, 오프라인 파일은 건너뜁니다. 클라우드 파일을 다운로드하지 않습니다.
- 건너뛴 항목 수는 확인한 항목 또는 디렉터리 수입니다. 접근할 수 없는 폴더 내부의 파일 수는 알 수 없습니다.
- 분석 중 파일이 변경되면 그 시점에 읽은 메타데이터가 반영됩니다. 볼륨 스냅샷을 만들지는 않습니다.
- 취소된 분석 결과는 확인한 범위만 포함합니다.

큰 파일 목록은 전체 검색 인덱스가 아니라 분석 범위에서 가장 큰 1,000개 파일입니다. 속도와 메모리를 위해 모든 파일 객체를 계속 보관하지 않습니다. 관리자 권한이나 원시 디스크 접근은 요구하지 않습니다.

## 개발 및 검증

```powershell
dotnet build src/WindowsFS.App/WindowsFS.App.csproj -c Release
dotnet run --project tests/WindowsFS.Core.Tests/WindowsFS.Core.Tests.csproj -c Release
dotnet run --project tests/WindowsFS.App.Tests/WindowsFS.App.Tests.csproj -c Release
```

별도의 테스트 프레임워크 패키지 없이 실행되는 코어 및 WPF 뷰 모델 검증 프로그램을 제공합니다. 분석 결과의 저장·복원과 잘못된 캐시 처리도 검증합니다. 테스트 파일은 임시 테스트 디렉터리에 생성하며, 실제 개인 파일 목록을 테스트 데이터로 저장하지 않습니다.

선택적으로 합성 파일을 생성해 분석 성능을 측정할 수 있습니다.

```powershell
dotnet run --project tests/WindowsFS.Core.Tests/WindowsFS.Core.Tests.csproj -c Release -- --benchmark
```

벤치마크는 임시 폴더의 합성 데이터로 실행하며 종료 후 정리합니다. 생성 직후의 파일을 읽으므로 첫 측정에도 OS 캐시의 영향이 있고, 반복 측정은 캐시가 더 준비된 상태입니다. 실제 전체 드라이브 분석이나 차가운 캐시 환경의 속도를 대표하는 수치로 해석하지 마세요.

```text
src/WindowsFS.App/         WPF 화면과 사용자 상호작용
src/WindowsFS.Core/        UI와 분리된 분석 엔진 및 결과 모델
tests/WindowsFS.Core.Tests/ 코어 동작 검증
tests/WindowsFS.App.Tests/  WPF 뷰 모델 동작 검증
scripts/                  로컬 실행 및 배포 스크립트
```

확장 지점과 성능 설계는 [아키텍처 문서](docs/architecture.md)에 정리했습니다.

## 저장소에 올리지 않는 정보

`.gitignore`는 로컬 SDK, 빌드 산출물, IDE 설정, 환경 변수 파일, 인증 키·인증서, 로그·덤프, 데이터베이스, 분석 캐시(`*.scan.json.gz`) 및 개인 분석 결과 폴더를 제외합니다. 기본 캐시 경로는 저장소 밖에 있습니다. 수동 분석 결과나 개인 테스트 파일은 `.artifacts/`, `scan-results/`, `exports/`, `local-data/`, `private/` 안에만 보관하세요.

`.gitignore`는 이미 추적 중인 파일이나 소스 코드 안에 직접 적힌 개인정보를 제거하지 않습니다. 커밋 전 `git diff --cached`와 `git status --short`로 실제 업로드 내용을 확인해야 합니다. 실제 파일 경로가 포함된 스크린샷이나 분석 결과는 이슈·PR·공개 저장소에 첨부하지 마세요.

커밋 작성자 이메일도 `.gitignore`의 보호 대상이 아닙니다. 개인정보 공개를 피하려면 저장소의 Git 설정에 GitHub에서 제공하는 `noreply` 이메일을 사용하세요.

## 파일 세부정보

일반 파일과 폴더를 선택하면 이름, 전체 경로, 상위 폴더, 종류, 분석 당시 논리적 크기·바이트 수와 비율을 표시합니다. 현재 크기와 생성·수정·액세스 시각, 파일 속성은 백그라운드에서 조회합니다. 접근할 수 없거나 삭제된 파일은 저장된 분석 정보와 상태를 표시합니다. 시스템 항목은 기존 설명도 함께 표시합니다.

파일을 선택하면 다음 형식의 미리보기를 자동으로 표시합니다. 여러 페이지 문서의 이전·다음 버튼과 페이지 번호는 미리보기 아래 중앙에 표시합니다. 오디오·영상 재생은 별도의 재생 버튼으로 시작합니다.

| 종류 | 지원 형식과 범위 |
| --- | --- |
| 이미지 | PNG, JPG/JPEG, BMP, GIF, TIFF, ICO. 최대 64 MB·1억 픽셀, 긴 변 1,600픽셀로 축소. GIF/TIFF는 첫 프레임 |
| 영상 | MP4/M4V, MOV, AVI, WMV, MKV, WebM 중 Windows 미디어 코덱이 지원하는 파일. 최대 2 GB, 재생 시간 제한 없음. 재생·일시정지·처음 버튼, 위치 이동 바, 현재 시간·전체 길이. 선택 변경·패널 숨김·종료 시 해제 |
| 오디오 | MP3. 최대 64 MB, 재생 시간 제한 없음. 재생·일시정지·처음 버튼, 위치 이동 바, 현재 시간·전체 길이. 자동 재생 없음. 선택 변경·패널 숨김·종료 시 해제 |
| PDF | 최대 64 MB, PDFium으로 페이지 표시와 이전·다음 이동. 링크·스크립트 실행 없음 |
| 문서 | DOCX/DOCM, XLSX/XLSM, PPTX/PPTM, HWPX, ODT/ODS/ODP를 페이지 이미지로 표시. 글꼴·크기·색상·강조·문단 정렬, 표·셀 배경·병합, 삽입 이미지와 이전·다음 페이지 이동 |
| 텍스트 | 기존 텍스트·소스 형식의 앞부분 64 KB, UTF-8/BOM. HTML도 텍스트로만 표시 |

문서는 최대 64 MB 파일에서 XML 파트당 2 MB·삽입 이미지당 8 MB·압축 해제 합계 32 MB 이내로 읽습니다. 최대 64 K 문자·100페이지, 삽입 이미지 40개·디코딩 합계 1,600만 픽셀, XML 깊이 64·요소 4만 개·레이아웃 요소 1만 2천 개로 제한합니다. Excel은 처음 10개 표시 시트·각 200행·50열을 여러 페이지로 나눕니다. 프레젠테이션은 처음 20개 슬라이드, HWPX는 처음 20개 구역을 표시합니다. 수식은 저장된 결과 값만 표시하며 재계산하지 않습니다. 매크로·외부 참조·XML 외부 엔티티는 실행하거나 조회하지 않습니다. 구형 DOC/XLS/PPT/HWP와 암호화 문서는 지원하지 않습니다.

내장 렌더러가 지원하는 서식을 재현하며 Office·한글과 픽셀 단위로 동일한 출력은 아닙니다. 설치되지 않은 글꼴, 테마·마스터·복잡한 도형·차트·수식 개체, 머리글·바닥글, 떠 있는 개체 배치, 일부 목록·사용자 지정 숫자 서식은 다르게 표시되거나 생략될 수 있습니다. 삽입 이미지는 PNG/JPEG/GIF/BMP/TIFF를 지원하며 SVG/EMF/WMF는 제외합니다. 문서 레이아웃은 별도 STA 스레드에서 계산하고 화면에는 고정된 페이지 이미지만 전달합니다.

미리보기 내용과 렌더링 이미지는 메모리에서만 처리하며 파일로 추출하거나 캐시에 저장·전송하지 않습니다. 링크·네트워크 경로·오프라인 파일은 제외합니다. 지원하지 않는 코덱, 손상·암호화·크기 제한 파일은 상태를 표시합니다. 디스크 할당 크기는 지원하지 않습니다.

MP3는 ID3v2 태그(최대 8 MB)를 건너뛰고 연속된 MPEG Layer III 프레임을 확인합니다. CBR/VBR 및 MPEG-1/2/2.5 헤더를 지원하며 free-format 비트레이트와 잘린 프레임은 제외합니다. 태그만 있거나 MP3 확장자로 위장한 외부 재생목록은 재생하지 않습니다.

재생 시작 시 미디어를 열어 전체 길이를 읽습니다. 위치 이동 바는 클릭·드래그·키보드로 이동하며 일시정지 중 위치를 옮겨도 일시정지를 유지합니다. 1시간 이상은 `시:분:초`로 표시합니다. 길이를 알 수 없으면 전체 길이는 `--:--`로 표시하고 위치 이동을 비활성화합니다. 일시정지 중 영상의 위치를 이동하면 해당 프레임을 표시합니다.

PDF 렌더링은 [PDFium의 V8 없는 배포본](https://github.com/bblanchon/pdfium-binaries), 영상 재생은 [WPF MediaElement](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/multimedia-overview)를 사용합니다. 문서 서식은 [Open XML 패키지](https://learn.microsoft.com/en-us/office/open-xml/about-the-open-xml-sdk), [HWPX 구조](https://tech.hancom.com/hwpxformat/), [OpenDocument 스키마](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part3-schema.html)에서 직접 읽어 WPF로 렌더링합니다. Office 설치나 셸 미리보기 처리기는 사용하지 않습니다.

세부정보 패널은 창 폭에 맞춰 늘어나며, 내부 폭이 충분하면 일반 정보와 시스템 설명을 2열로 표시합니다. 좁은 창에서는 1열로 돌아옵니다.
